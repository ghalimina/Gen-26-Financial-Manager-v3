## 3. Mathematical Details of Key Contract Discrepancies

### A. The Breadth Lookahead Leakage
* **The Locked Specification Formula:**
  $$\text{Breadth\_AdvanceRatio}_t = \frac{1}{M_t} \sum_{i=1}^{M_t} \mathbf{1}_{\{\text{Fwd\_Ret\_1D}_{i,t} > 0\}}$$
  Where $\text{Fwd\_Ret\_1D}_{i,t} = \frac{Close_{i,t+1} - Close_{i,t}}{Close_{i,t}}$.
* **The Mathematical Reality:**
  To compute this value at market close on day $t$ (14:30 Cairo time), the algorithm requires the closing price of day $t+1$. This is a forward lookahead of 24 hours. Because stocks with positive forward 1-day returns are strongly correlated with positive 20-day returns, the indicator selected stocks that were already guaranteed to rise the next day.
* **The Clean Replacement:**
  $$\text{Breadth\_AdvanceRatio\_CLEAN}_t = \frac{1}{M_t} \sum_{i=1}^{M_t} \mathbf{1}_{\{\text{Ret\_1D\_Trailing}_{i,t} > 0\}}$$
  Where $\text{Ret\_1D\_Trailing}_{i,t} = \frac{Close_{i,t} - Close_{i,t-1}}{Close_{i,t-1}}$.

### B. The Entry Timing Contract Discrepancy
* **Contract Specification:**
  $$\text{Target Return}_{\text{Contract}} = \frac{Close_{t+20} - Open_{t+1}}{Open_{t+1}}$$
* **Actual Code Implementation:**
  $$\text{Target Return}_{\text{Code}} = \frac{Close_{t+20} - Close_{t}}{Close_{t}} = \text{Fwd\_Ret\_20D}_t$$
* **Empirical Discrepancy Measurement across Universe ($N = 42,641$ bars):**
  * Mean Difference ($\text{Return}_{\text{Contract}} - \text{Return}_{\text{Code}}$): **$-0.0033\%$** (Negligible mean bias).
  * Standard Deviation of Difference: **$0.425\%$** (Overnight volatility noise).
  * Maximum Single-Stock Favorable Gap: **$+8.69\%$** (Understated return in code).
  * Maximum Single-Stock Adverse Gap: **$-5.99\%$** (Overstated return in code).

### C. The Profit Factor Formula Ambiguity
* **True Net Profit Factor Formula:**
  $$\text{PF}_{\text{Net}} = \frac{\sum_{i: r_i - c > 0} (r_i - c)}{\sum_{i: r_i - c < 0} |r_i - c|}$$
* **Code Implementation in `phase1_cost_aware_baselines.py` (lines 148–151):**
  ```python
  gw = gross[gross > 0].sum()
  gl = abs(gross[gross < 0].sum())
  pf = gw / (gl + 1e-9)
  ```
  The code computed **Gross Profit Factor** ($\sum r^+ / |\sum r^-|$) but reported it in tables labeled "Net Profit Factor after 0.90% RT cost". For `BL3_Momentum` in development:
  * Gross PF = **`2.212`**
  * Reported Baseline PF = **`2.138`** (Fold-average gross)
  * True Net PF = **`1.821`**
  The baseline bar against which all subsequent phases were evaluated was inflated by $+0.317$ due to the omission of friction from the profit factor ratio itself.
